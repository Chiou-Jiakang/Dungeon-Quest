# Dungeon Quest 遊戲設計規格

## 1. 文件資訊

- 文件版本：0.1
- 建立日期：2026-11-25
- 狀態：初始設計草案

除已完成的 M0 原型外，本文件數值及規則均為預定設計，
將依後續開發與遊戲平衡測試調整。

## 2. 遊戲定位

Dungeon Quest 是一款單人、2D 像素風格、
俯視角、格子移動及回合制地下城角色扮演遊戲。

玩家探索地下城、擊敗敵人、取得道具並提升能力，
最終挑戰地下城 Boss。

## 3. 核心遊戲循環

進入地下城
→ 探索地圖
→ 遭遇敵人
→ 戰鬥
→ 取得獎勵
→ 強化角色
→ 挑戰下一層
→ 擊敗 Boss

## 4. 玩家角色

正式版預計提供一名冒險者（Adventurer）。

| 屬性 | 初始規劃值 |
| --- | --- |
| Level | 1 |
| HP | 100 |
| Max HP | 100 |
| ATK | 15 |
| DEF | 5 |
| EXP | 0 |
| Gold | 0 |
| 小型生命藥水 | 2 |

## 5. 敵人設計

| 敵人 | 類型 | HP | ATK | DEF |
| --- | --- | ---: | ---: | ---: |
| Slime | 基礎敵人 | 30 | 6 | 3 |
| Skeleton | 近戰追擊 | 50 | 12 | 4 |
| Bat | 高機動敵人 | 25 | 8 | 2 |
| Abyss Knight | 最終 Boss | 200 | 25 | 10 |

以上為初始平衡測試候選數值，尚未實作。

Boss 預計依生命值比例切換攻擊階段。

## 6. 地圖與移動

- 地圖以二維陣列儲存。
- 0 代表可通行地板。
- 1 代表不可通行牆壁。
- 角色只能在合法格子中移動。
- 初期採上、下、左、右四方向移動。
- 玩家與敵人的位置獨立於地形資料。
- 不允許角色穿牆、超出地圖或非法重疊。
- WASD 與方向鍵作為預定操作方式。

正式版預計包含兩層地下城及最終 Boss。

## 7. 戰鬥系統

預計採用回合制戰鬥。

玩家完成一次有效行動後，
由存活敵人依固定順序執行各自的行動。

無效行動不消耗回合。

初期普通攻擊傷害公式：

    Damage = max(1, ATK - DEF)

基本規則：

- 近戰攻擊目標必須在合法攻擊範圍內。
- HP 不得小於 0 或高於 Max HP。
- HP 歸零時觸發死亡判定。
- 死亡角色不得繼續行動。
- 同一敵人的死亡獎勵不得重複發放。

後續加入技能、裝備加成與 Boss 特殊行為。

## 8. 敵人 AI

預計使用有限狀態機（FSM）。

| 狀態 | 職責 |
| --- | --- |
| Idle | 待機 |
| Patrol | 巡邏 |
| Chase | 追擊玩家 |
| Attack | 攻擊玩家 |
| Dead | 停止行動 |

追擊階段使用 A* 尋路演算法。

當路徑不存在時，敵人必須安全停止移動，
不得進入無限搜尋或穿越障礙物。

## 9. 道具與背包

| 道具類型 | 用途 |
| --- | --- |
| Potion | 恢復生命值 |
| Weapon | 提升攻擊能力 |
| Armor | 提升防禦能力 |
| Key | 解鎖特定區域 |

背包須處理道具取得、使用、裝備及數量檢查。

金幣及 NPC 商店可於後續版本擴充，
商店不列為 v1.0.0 必要功能。

## 10. 勝利與失敗

勝利條件：擊敗最終 Boss。
失敗條件：玩家 HP 歸零。

遊戲應提供勝利、失敗及重新開始的介面。

## 11. 存檔系統

預計以 localStorage 儲存遊戲資料，
包含角色狀態、背包、目前樓層及必要關卡進度。

存檔應具備版本編號、資料驗證及損壞處理。

## 12. 美術及介面

- 暗色奇幻風格（Dark Fantasy）。
- 石磚地下城、深灰及古銅金配色。
- 初期使用幾何圖形作為測試素材。
- 正式版逐步加入像素角色、地圖及道具素材。
- 第三方素材必須記錄來源及授權。

## 13. 範圍限制

v1.0.0 不包含：

- 多人連線。
- 線上帳號系統。
- 雲端存檔。
- 大型開放世界。
- 複雜職業與技能樹。
- 強制隨機生成地牢。
