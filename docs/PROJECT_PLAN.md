# Dungeon Quest 專案開發計畫

## 1. 專案目標

完成具備地圖探索、敵人 AI、尋路演算法、
回合制戰鬥、角色成長及存檔功能的地下城 RPG。

正式發布目標：v1.0.0。

初始工期估計：7 至 10 週。
實際工期依開發與驗收情況調整。

## 4. 里程碑驗收條件

### M1

- 玩家可使用鍵盤移動。
- 四方向移動規則正確。
- 不允許穿牆或超出地圖。
- 建立地圖及移動相關自動化測試。

### M2

- 自行實作 A* 尋路演算法。
- 使用合法且可通行的地圖節點。
- 能找到最短路徑。
- 正確處理無路徑及非法座標。

### M3

- 完成敵人 FSM。
- 支援巡邏、待機與追擊決策。
- 整合 A* 尋路。
- 敵人狀態與移動規則通過測試。

### M4

- 完成回合管理與攻擊。
- 正確處理 HP、傷害及死亡。
- 防止重複行動或重複死亡事件。
- 建立戰鬥日誌及相關測試。

### M5

- 完成經驗值與升級。
- 完成背包、道具與裝備。
- 防止非法道具使用及負數庫存。

### M6

- 完成地下城樓層切換。
- 加入寶箱、敵人獎勵與 Boss。
- 完成勝利與失敗條件。

### M7

- 完善遊戲主選單、HUD 及背包介面。
- 加入存檔與讀檔。
- 處理損壞或不相容的存檔。
- 加入適當授權的美術及音效。

### M8

- 完成單元、整合及瀏覽器測試。
- 完成完整通關測試。
- 檢查效能、建置容量及錯誤處理。
- 修正阻礙正式發布的問題。

### M9

- 更新所有專案文件。
- 完成最終建置及發布驗收。
- 建立 v1.0.0 Git Tag。
- 發布 GitHub Release。

## 5. 開發管理流程

需求定義
→ 程式實作
→ 功能驗收
→ 修正問題
→ 更新文件
→ Git Commit
→ Git Push

未通過驗收的功能不得直接標示為完成。

## 6. 版本管理

- 目前版本：0.0.0。
- 預計主要分支：main。
- 正式發布目標：v1.0.0。
- 每個重要功能完成後建立具描述性的 Commit。
- 不提交 node_modules、dist 或敏感資料。
- 保留 package-lock.json。

## 7. 風險管理

| 風險 | 處理策略 |
| --- | --- |
| 功能範圍過大 | 優先完成 v1.0.0 核心功能 |
| Phaser API 相容性 | 固定引擎版本 |
| AI 或尋路錯誤 | 獨立模組與自動化測試 |
| 回合或戰鬥狀態混亂 | 統一行動驗證及狀態管理 |
| 美術素材授權問題 | 記錄來源及授權 |
| 建置檔案容量 | M8 評估效能改善 |
| 文件與程式不同步 | 每階段同步更新 |
